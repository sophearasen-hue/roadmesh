## How it is measured

* **Conflict:** using the vehicles' true positions and their real planned routes (including the turn each driver has decided on), with nobody reacting, two outlines would touch within 3 s. Only pairs where both have the app count, because a phone can only warn about vehicles that broadcast.
* **Warned in time:** either phone showed a Warning or Danger about the other before the predicted touch came closer than 1.5 s (allowing 0.5 s for radio and processing; an alert shown in the last second counts). Otherwise the conflict is **missed**.
* **False alarm:** a Warning or Danger about another vehicle when, with true positions and no reaction, the two would never come within 1 m of each other in the next 8 s.
* **GPS confidence gate:** SPEC §6 allows only a Caution for vehicles whose phone reports worse than 8 m accuracy, so those pairs are shown separately.
* The phones run the real Rust core (spec profile) with GPS smoothing and map matching. Drivers with the app react to a Warning or Danger after 1 s and follow the braking advice. Signature checks are off in these runs to keep them fast; the check at the end shows they change nothing.

## Limits of this simulation

* The radio is a simple model (150 m in sight, 60 m around buildings, random loss); Step 5 replaces it with field measurements.
* Relaying is off except in the relaying section.
* GPS error drifts slowly (30 s) like real phones, plus a little jitter.
* Drivers follow simple rules; real Cambodian traffic (motorbikes filtering between lanes, wrong-way riders) is more varied.
* The ground truth uses the same kind of motion model as the core for the 3 s window; crashes in the simulation do not depend on it.
